# Contributing to kixctl

**Environment setup lives in the docs:** [Running from source](https://kixctl.com/docs/contributing/run-from-source) covers the Nix dev shell, the services you provide (Postgres, Valkey, an Incus cluster), and the bring-up. Start there.

## Before a pull request

- Format with php-cs-fixer (`.php-cs-fixer.dist.php` is in the repo).
- Run the test suite (`phpunit.xml`).

## Contributions and licensing

kixctl is dual-licensed: AGPL-3.0-or-later, or a commercial license. For that to work, contributions have to be usable under both.

By submitting a contribution, you grant the project a broad, perpetual, irrevocable license to use, modify, and relicense your contribution — including as part of the commercial edition — with no obligation of compensation. You keep the copyright to your own work; this grant is what lets the project ship it under both licenses.

This is the standard arrangement for dual-licensed open source, and it exists so the commercial edition can fund the open one — not to take anything away from you. If you don't want your contribution used under the commercial license, don't submit it, and open an issue to discuss instead.

The formal contributor agreement is still being finalized; this section states the intent. Substantial contributions should start with an issue so the terms are settled before you invest the work.
